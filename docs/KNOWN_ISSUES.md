## 尚未关闭的独立复核问题

以下来自 backend 最终限定复核报告及其源码位置，lead 本次未独立执行失败探针，不能把它们标为独立复现或已修复：

1. **刷新请求发出后取消，同进程可能再次使用一次性 refresh token。** 磁盘已有 refresh_pending 栅栏，但取消路径没有充分设置进程内错误状态；随后同一 Auth 进程再次取凭证可能重发。必须保留为待修项，不能将磁盘重启保护等同于同进程保护。
2. **发送前栅栏写失败可能被仍有效的旧 access token 掩盖。** 调用可能返回 nil 错误，后台也没有足够故障报告；需要补“写栅栏失败必须可观测”的回归和修复。

现有自动化测试未覆盖上述完整断言；即使现有 test/race 全通过，也不消除此处的复核否决。

## 存储故障边界

原子替换后目录同步失败，新文件可能已可见但持久性不确定；不能报告为“旧文件必然保留”。文件系统同时拒绝失效状态写入与隔离时，独立 API 仅靠旧文件无法知道 Auth 内存中的拒绝状态。详见 [凭证契约](CREDENTIALS.md)。这些限制被披露，不代表已获技术验收豁免或自动解决。
