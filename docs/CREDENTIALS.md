# TRAE-008 凭证文件契约

固定路径：`filepath.Join(os.UserConfigDir(), "trae-api", "auth.json")`。不提供自定义路径、旧文件迁移或清理入口。macOS 测试须设置隔离 `HOME`；仅设置 `XDG_CONFIG_HOME` 不足以隔离 `os.UserConfigDir()`。网关的 `TRAE_API_TOKEN` 是调用本地 API 的访问保护，不是本文件里的 Trae 上游访问 Token。

版本 1 的 JSON 字段：`version`、`token`、`expires_at`、`user_id`、`client_id`、`device_id`、`machine_id`，以及仅 Auth 使用的 `refresh_token`、`refresh_expires_at`、`device_private_key`（base64 编码的 P-256 PKCS#8 私钥）、`refresh_pending`（一次性 refresh 发送前写入的持久化栅栏）。Auth 校验完整版本和私钥后恢复/续期；若上次刷新结果不确定，栅栏阻止重启后重发可能已消耗的 refresh token，尚有效的 access token 可继续使用直到到期或重新登录。有效刷新完成后才原子清除栅栏；API 用独立窄结构体解码，只读取访问 Token、有效期及请求所需标识，忽略私密续期字段。API 每次请求读完整快照，不调用 Auth 来续期、不在上游 401/403 后重放。失效或缺失的快照需要重新登录/等待 Auth 续期。

新建应用目录为 0700、文件和稳定的 `auth.json.lock` 为 0600。Auth 在生命周期内持有 sidecar 排他锁，第二写者拒绝启动；写入在同目录受限临时文件完成、文件同步并关闭后原子替换，随后尝试同步目录；替换前失败保留原文件，临时文件清理。损坏、未知版本、不安全权限、非普通文件和符号链接均拒绝，不自动覆盖或删除未知用户数据。Auth 确证收到上游 401/403 时原子写入已失效状态；若原子写失败，尝试把已拒绝的当前文件改名隔离至同一私有目录（不删除），使 API 固定路径读不到旧令牌，并允许后续重新登录。若文件系统连这一步也失败（例如整个卷只读），独立 API 进程无法凭旧文件知道 Auth 的内存状态；该不可保证情形必须报错并作为残余故障处理，不能宣称失效状态已落盘。**目录同步若在原子替换后失败**，调用返回错误但新文件可能已经可见；Auth 精确回读包括 refresh token、有效期和设备密钥的目标快照，只有完全一致才更新内存，同时向调用方报告持久化未确认。回读不一致则保留旧内存和不重发栅栏，不重放可能已消耗的 refresh token。登录回调的此类故障返回 503、状态 `durability_uncertain`，CLI 会提示重新登录；定时刷新会记录不含凭证的警告。重新登录在该状态下可发起。文件替换前失败保持原文件；发送 refresh 前的栅栏写失败时不得发出网络请求。即便回读匹配，也不保证崩溃后的目录项已经落盘，不能将该类错误报告成“旧文件必然保留”。

这种分工是进程内的职责隔离，不是同一 OS 用户下的物理秘密隔离。测试仅使用合成凭证、本机 mock 和隔离目录；真实浏览器授权与 Trae 模型调用尚未验证。
